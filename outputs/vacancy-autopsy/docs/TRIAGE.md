# Budgeted prediction agent

Shortlist can accept separate public job links or a pasted list. **Investigate within budget** runs the Mastra prediction workflow: `triage` freezes the six pre-verification features, calls the existing TabPFN service and validates the relative ranking; `verify-within-budget` checks only the selected leads. The default budget is three, capped by the number of leads. Equal scores keep competition ranks and the service's deterministic tie order. A priority score never supplies an availability verdict.

`POST /api/triage` accepts `{ entries, budget? }`. Entries use the existing priority schema, with optional advertisement text. The response contains ranked leads, checked/skipped reasons, actual saved report references, checks used, checks saved and history rows. `GET /api/triage/history` returns the history count and `automaticRetraining: false`. Both routes use the hosted workspace's existing Auth0 gate. There is one active triage request per process, bounded execution and no automatic verification retry. After a browser timeout, inspect Saved checks before starting again.

Unknown age, repost count, employer similarity and title consistency remain null. An explicit supported ATS URL supplies ATS-link presence and source type. Neither a later source response nor its verdict can alter the frozen feature vector.

After a verification returns and its report is saved, the workflow appends a private JSONL observation. History follows the existing feature/verification/gold record structure, explicitly marked `agent_collected`, `review_required: true` and `training_eligible: false`. It uses `agent_first_party_check`, never independent or human review. Uncertain outcomes remain null, and employer/title gold labels remain unknown. A pasted URL is not an independently captured advertisement; its capture timestamp stays null. History counts observations, including rechecks, rather than unique training examples. The strict benchmark loader rejects this schema. There is no automatic training.

New writes use history schema v2. The reader accepts earlier v1 rows without modifying their bytes. Local history is `data/triage/history.jsonl`, or the configured `DATA_DIR`. Hosted history uses an explicit `DATA_DIR` or a sibling of the persistent TabPFN context: the current Render configuration resolves to `/var/lib/vacancy-autopsy/triage/history.jsonl`. Hosted mode without either location leaves triage unconfigured. The file is owner-only, appends are serialized and synchronized, and identical history IDs are idempotent. One application instance is required.

## Executed evidence

A real local browser run on November 1 ranked four retained public posting leads, verified three, skipped one and saved three history rows. The leads tied on the supplied features: this proves budget execution, not a learned ordering advantage on that batch. Its downloaded report matched the history reference and all retained evidence-body hashes. A deliberate API restart preserved the history bytes and count. The browser also exercised bulk paste by keyboard at a 390-pixel viewport with no horizontal overflow. Receipts and screenshots are at the workspace root under `outputs/evidence/triage-local.json`, `triage-local.png` and `triage-mobile.png`. These observations establish this local journey; hosted execution needs its own receipt.

Focused synthetic tests separately cover budgets, nulls, malformed rankings, uncertain/failed checks, cancellation, private storage, legacy compatibility, refusal by the benchmark loader and hosted authorization. They establish code behavior rather than provider accuracy. See `tests/triage.test.ts` and the executed log `outputs/evidence/triage-tests.txt` at the workspace root.
