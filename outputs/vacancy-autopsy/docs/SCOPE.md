# Vacancy Autopsy — working scope

For job seekers deciding whether to invest time in an advertised opening. Outcome: inspect a timestamped, reproducible first-party check before applying.

Implemented journey: enter through the public product landing, submit an official Greenhouse, Lever or Ashby job URL (or supply one alongside an advertisement), read a qualified finding and next action, then save/download or recheck as needed. The trained Tinker reader suggests listing identity; TabPFN orders a user-entered shortlist using pre-verification features. Tinker training, TabPFN evaluation and live browser entry points for both models have run. SerpApi has returned real advertisement candidates, Sentry has received sanitized workflow/tool traces, and the local app now saves reports and source artifacts in a dedicated Atlas cluster. Nine original sponsors have meaningful run evidence, including a real Browserbase capture and Auth0 reviewer approval persisted in Atlas; this is not nine accepted categories. SerpApi's exact first-party-counterpart discovery and the Render hosted release remain open.

Acceptance: live public ATS requests; strict job-ID matching; incomplete/error responses remain inconclusive; hashed evidence with capture times; persistence/recheck; responsive keyboard-operable UI; honest loading, empty and unavailable states; tested failure cases. No automatic applications or unsupported employer-intent claims.

Phases: (1) official-source verifier and useful UI; (2) real labeled corpus and model experiments; (3) sponsor services and recovery/approval evidence; (4) deployment and submission only under user authorization.

Constraints: no Arduino or DigitalOcean. Routine local implementation, verification and Entire setup are authorized. Hosting boundary: localhost by default. Optional hosted mode requires a public HTTPS origin, complete Auth0 configuration and MongoDB persistence. Every permitted human reviewer shares one private workspace; tenant isolation is not implemented. Optional public source snapshots are separately confirmed, digest-bound, sanitized and withdrawable; sharing stays off by default and in the actual app configuration. Their sharing tests use generated JWTs and synthetic evidence; real Auth0 private approval is separately verified, and no real finding was published. Real Atlas migration, scoped access and browser restart persistence have passed. Local product reviewer login and private approval are verified. An authorized real publication and a hosted journey remain release gates; the current single-address Atlas network rule permits only this machine.

Observed lead: the OppIDX Figma advertisement still presented an Apply link to job `6144755004`; the complete employer feed did not contain that ID and the application URL redirected to careers. This is a point-in-time mismatch, not evidence of intent or prior removal.

Naming: Vacancy Autopsy. Tagline: The internet remembers jobs that employers have already removed. This describes the problem hypothesis, not proof that a particular employer removed an opening.

Evidence vocabulary: "Verified open" means the exact posting is in the checked public source at the recorded time, not that a hire will happen. "Not currently listed" means absent from a successfully validated complete public board response, not proved fake or fraudulent. "Inconclusive" covers ambiguous identity, access errors, rate limits, partial data, and unsupported sources. A prior timestamped positive observation is needed to claim that a posting was removed.
