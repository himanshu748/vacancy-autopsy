# Current alternatives with Ultramarine

An absent posting leaves an applicant with another task: find a relevant opening that is actually present in the employer's checked inventory. The optional **Could another opening fit?** panel compares a public role title and optional public location with that inventory. It offers possible alternatives, never a claim that an opening was reposted or that two posting IDs are the same job.

Configure the dedicated server-only `PAPERINSTRUMENTS_API_KEY`. The panel stays hidden without it. The user explicitly starts each comparison; opening a report never invokes the model. The authenticated endpoint is `POST /api/investigations/:id/alternatives`, accepting only `{ role, location? }`. It requires a live `not_listed` report checked within the freshness window. The report's availability finding remains unchanged.

The server checks saved source-body hashes and replays the existing complete-feed verifier without networking. It accepts only supported exact ATS posting links whose board, region and ID match the native source record. Custom career domains and query-only job identities are omitted. It preselects a bounded pool by title overlap, then asks Ultramarine to select actual IDs. Output titles, URLs and locations are copied from retained source records; the model cannot supply them. Reasons use a fixed vocabulary, and unlisted or duplicate IDs are rejected.

Only the explicitly supplied public role/location and candidate IDs, titles and locations reach Paper Instruments. Advertisement text, complete source bodies, reviewer identity, access tokens and other model state are excluded. Source text is untrusted data, the model has no tools, and selected candidates are not availability verdicts. Suggestions refer to the saved check time and can become outdated.

The official OpenAI SDK calls the fixed Paper Instruments endpoint and `ultramarine-1-flash`, with storage disabled, bounded reasoning/output, a timeout and automatic retries disabled. A per-process lock prevents simultaneous model calls even when database reads overlap. Returned usage is validated; missing token details remain unknown. The response reports actual returned token counts and a gross uncached cost estimate using the [official pricing endpoint](https://api.paperinstruments.com/v1/pricing). This estimate includes output reasoning tokens, excludes cache discounts, and is not a verified invoice. The pricing snapshot is retained locally as `outputs/evidence/ultramarine-pricing.json` at the workspace root.

Focused tests cover all three ATS source families, source tampering/completeness, exact link binding, unknown model IDs, prompt injection, privacy projection, SDK usage, missing settings and concurrent requests. A successful synthetic test or configured key does not establish a live provider run. Record a separate actual browser/provider receipt before claiming this integration as executed.

## Executed hosted run, November 1, 2026

The authenticated Render application compared the public role title “Brand Design Intern (Summer 2027)” with a retained complete employer feed. Title preselection supplied 20 candidates from 140 supported postings; Ultramarine selected three possible alternatives. The returned usage was 792 input tokens, 47 output tokens, zero cached input tokens and one reasoning token within the output total. The measured model comparison took 1,446.08 ms. At the recorded official rates, its token-cost estimate is **$0.0001423**, not a verified invoice.

The comparison was downloaded through the product. Independent replay confirmed every selected ID, title and URL against the saved official feed, all evidence hashes, the usage totals and the pricing version. The finding remained “Not currently listed”; suggestions were explicitly different posting IDs and not confirmed reposts.
